## Architecture Pattern

**Layered (presentation / business_logic / data) with BLoC Cubit state management.** Not strict Clean Architecture — there is no `domain/usecases` layer, and most cubits call Dio directly instead of going through a repository. Only `AuthRepo` exists.

## Import / Dependency Flow

```
presentation/<Screen>  →  business_logic/<Feature>Cubit  →  data/Services/*ApiService (Dio)  →  signlingo.org/api/
                                                        ↘  data/Repos/AuthRepo (auth feature only)
                                                        ↘  on-device ML (sign_language_classifier + HandLandmarker)
                                                        ↘  CacheHelper (shared_preferences) for token / lang / mode
```

Localization is read at every rebuild from `CacheHelper.getData('lang')` and applied via `S.load(Locale(...))`.

## On-device ML pipeline

`lib/data/Services/sign_language_classifier.dart` loads `Assets/models/sign_lstm_attention_fp32.onnx` at startup (non-blocking, kicked off from `main()`). MediaPipe Hand Landmarker runs **natively on Android** via `android/app/src/main/kotlin/com/example/graduation_project/HandLandmarkerService.kt` (called over a platform channel from `mediapipe_hand_service.dart`). Per-frame 21×3 left+right hand keypoints (126 features) are buffered and resampled to 30 frames in `SendFramesCubit`, fed to the ONNX LSTM-attention model, then softmaxed and mapped through `lib/data/Models/labels_map.dart`. Below the 50% confidence threshold, the prediction falls back to "غير معروف". UI is `presentation/VideoTranslation/handtrackingview.dart`.

Voice translation goes the other way: `speech_to_text` captures speech → `VoiceTranslationCubit` → plays a corresponding sign-language video via `video_player`/`chewie`. UI is `presentation/VoiceTranslation/voice_translation_page.dart` plus `widgets/mic_button.dart` and `widgets/transcript_card.dart`.
