## Architecture Pattern

**Layered (presentation / business_logic / data) with BLoC Cubit state management.** Not strict Clean Architecture — there is no `domain/usecases` layer, and most cubits call Dio directly instead of going through a repository. Only `AuthRepo` exists.

## Import / Dependency Flow

```
presentation/<Screen>  →  business_logic/<Feature>Cubit  →  data/Services/*ApiService (Dio)  →  signlingo.org/api/
                                                        ↘  data/Repos/AuthRepo (auth feature only)
                                                        ↘  on-device ML (sign_language_classifier + HandLandmarker)
                                                        ↘  CacheHelper (shared_preferences) for token / lang / mode
```

Localization is read at every rebuild from `CacheHelper.getData('lang')` and applied via `S.load(Locale(...))`.

## On-device ML pipeline

`lib/data/Services/sign_language_classifier.dart` loads `Assets/models/sign_lstm_attention_fp32.onnx` at startup (non-blocking, kicked off from `main()`). The MediaPipe `hand_landmarker` package extracts hand keypoints from camera frames (`SendFramesCubit`); these are fed into the ONNX LSTM-attention model which outputs class indices mapped through `lib/data/Models/labels_map.dart`. UI is `presentation/VideoTranslation/handtrackingview.dart`.

Voice translation goes the other way: `speech_to_text` captures speech → `VoiceTranslationCubit` → plays a corresponding sign-language video via `video_player`/`chewie`.
